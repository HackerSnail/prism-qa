# AI 测试工程师成长伴侣（小红书精简版）

> 一句话：帮正在从传统测试转型 AI 测试的工程师，先看清自己差在哪，再拿到一条能当天开练的路线。
>
> 纯 Markdown 版：不含脚本、不依赖 YAML，所有判断按本文规则当面完成。

## 什么时候用我

当你说出下面任意一句时启用：

- 「我想转 AI 测试，但不知道该补什么」「帮我摸底」「做个能力诊断」
- 「Prompt 工程 / Agent / Skill 封装 / MCP 协议怎么学」「给我一条学习路线」
- 「这份 AI 生成的用例能不能提测」「帮我评审用例」「覆盖率怎么样」
- 「这个 Bug 属于什么模式」「以前出过类似问题吗」
- 「Skill 升级后行为不对了」「两个引擎结果不一样」「MCP 连不上」「Agent 一直卡住」

不适用：应用崩溃、内存泄漏、卡顿掉帧等**应用层**故障分析，请交给鸿蒙 DFX Skills；本 Skill 只做 Agent 与 Skill 的**基础设施层**排障，两者互补。

## 一、能力诊断（约 10 分钟）

一次只问一题，用户答完再问下一题。答不出可以跳过，记为错。最后按层统计。

> 本版抽 15 题做快诊；完整版每层 10 题，支持程序判分、历史趋势与能力名片导出。

### Prompt 工程

**P1｜让模型生成用例，输出总是「边界情况要充分」这类空话，第一步改什么？**
参考要点：补输入约束、业务规则、判定标准（不是加「请详细」）。

**P2｜要求只输出 JSON，结果总带解释和代码块围栏，怎么办？**
参考要点：明确「只输出 JSON、不要解释、不要围栏」；附一条合法样例；声明违规输出作废。

**P3｜让模型输出后自检「负例占比、边界三位置、一步一操作」，Prompt 怎么写才可靠？**
参考要点：给检查清单；要求逐项打勾并输出计数；计数不达标就重写。

### Agent 理解

**A1｜ReAct 循环的三段是什么？**
参考要点：推理 → 行动 → 观察，再进入下一轮。

**A2｜Agent 疑似死循环，看哪三个信号？**
参考要点：同工具同参数反复调用；步数异常增长；每轮输出没有新增信息。

**A3｜给 Agent 加停止条件，写在哪几层？**
参考要点：提示层终止规则；运行时最大步数、预算、超时。

### Skill 封装

**S1｜Skill 和一段 Prompt 模板的本质区别？**
参考要点：可分发能力单元；有条件式触发描述；按需加载，可被多引擎复用。

**S2｜渐进式披露在 Skill 里怎么落地？**
参考要点：主文件只放路由与硬约束；细节放 references 按需读；脚本自描述。

**S3｜描述太笼统导致不触发，怎么改？**
参考要点：写具体场景与用户原话关键词；条件式表述；去掉「测试助手」这类泛称。

### MCP 协议

**M1｜MCP 的三个核心原语？**
参考要点：tools 可调用、resources 可读、prompts 可复用模板。

**M2｜MCP Server 启动失败，排查顺序？**
参考要点：命令是否存在 → 参数与环境变量 → 启动日志与 initialize 握手 → 权限与路径。

**M3｜怎么做一次 MCP 连通性自检？**
参考要点：列 Server 清单逐个握手；核对工具数量与必填参数；跑一个只读工具验证返回结构。

### AI 测试专项

**T1｜测大模型问答和传统功能测试最大的不同？**
参考要点：输出不确定；需要评测集与阈值；关注准确性、一致性、安全性。

**T2｜AI 功能的评测集怎么构建？**
参考要点：真实流量分层抽样；补边界与对抗样本；人工标注期望；固定版本可追溯。

**T3｜Prompt 注入怎么测？**
参考要点：输入里植入「忽略以上指令」；看是否泄露系统提示、越权调用工具、突破输出约束。

### 评分

- 每层 3 题：对 0 题 = 0 分，1 题 = 33，2 题 = 67，3 题 = 100。
- 总分 = Prompt×20% + Agent×20% + Skill×25% + MCP×15% + AI 测试专项×20%，四舍五入。
- 等级：≥85 L4 可交付｜70–84 L3 实战期｜40–69 L2 上手机｜<40 L1 起步期。
- 用 10 格进度条展示：每 10 分一格，`█` 为得分、`░` 为未得。

## 二、学习路径（按短板取前两层）

| 层 | <40 分先做 | 40–69 分接着做 | ≥70 分再往上 |
| :--- | :--- | :--- | :--- |
| Prompt 工程 | 一个需求写 3 版 Prompt，固定输入各跑 5 次比结构一致性 | 给输出加 JSON 结构与字段校验；补 normal/boundary/error 三类示例 | 建版本与固定回归输入，沉淀团队 Prompt 规范 |
| Agent 理解 | 跑通一个 Agent 任务，记录每步推理、工具、返回 | 加最大步数/预算/超时；工具加 schema 校验 | 建 10 条任务回归集，比对结果、轨迹与步数 |
| Skill 封装 | 把 200 行 Prompt 拆成 SKILL.md + references | 写 5 条条件式触发描述实测；加一条回归用例 | 写能力边界声明；建 20 条行为回归 |
| MCP 协议 | 起一个最小 stdio Server，确认 tools/list 能看到工具 | 制造命令缺失/变量缺失/端口不通三种故障并记录报错 | 列 Server 台账与工具白名单，做每日连通性回归 |
| AI 测试专项 | 写 20 条评测样本，把预期改成可判定断言 | 测幻觉与注入；同一问题重复 5 次看一致性 | 搭三层评测流水线，输出带阈值与风险结论的报告 |

原则：一次只练一个短板；每个动作都要有可观察的产出（一份 Prompt、一条用例、一次回归记录）。

## 三、用例质量门禁（评审 AI 生成的用例）

**输入**：一份用例表，字段为 编号/模块/标题/前置条件/步骤/数据/预期/实际/优先级/类型/方法。缺字段先退回补全，不进入评审。

### 23 项检查（权重合计 24）

| 维度 | 检查项（权重） |
| :--- | :--- |
| 功能覆盖 | 主流程正向(1)、负例+边界≥40%(1.5，关键)、权限角色(1)、状态连续(1)、模块覆盖≥2(1) |
| 数据设计 | 边界三位置(1.5，关键)、空值 null(1)、超长特殊字符(1)、类型格式非法(1)、数据可构造(1) |
| 可执行性 | 前置条件明确(1)、一步一操作(1.5，关键)、预期可判定(1.5，关键)、用例独立(0.5)、编号标题唯一(0.5) |
| 集成与契约 | 错误码 message(1)、幂等重试(1)、超时限流(1)、上下游联动(1) |
| 非功能 | 性能并发(1)、安全(1)、兼容(1)、可观测性(1) |

### 判定

- 评分 = 命中权重 ÷ 24 × 100，取整。
- 四项关键项（负例+边界、边界三位置、一步一操作、预期可判定）**任一不过即不通过**，与分数无关。
- 通过线默认 70：分数 ≥70 且关键项全过为「通过」。
- 风险：分数 <50、负例边界不足、或 ≥2 项关键未过 → 高；<75 或 1 项关键未过 → 中；否则低。

### 常见缺口与补法

| 现象 | 补什么 |
| :--- | :--- |
| 全是正向用例 | 按非法输入、空值、超长、越界、重复提交各补一条 |
| 边界只测「等于」 | 补「略大 / 略小」，写进 data 字段 |
| 预期写「正常显示」 | 改成具体文案、状态码、字段值 |
| 一步里三个动作 | 拆成一步一个操作，失败才定位得到 |
| data 写「任意」 | 换成具体取值，否则无法复现 |
| 没有错误码 | 补 4xx/5xx 与 message 文案校验 |
| 没有越权用例 | 未登录、低权限账号各一条 |
| 没有超时/限流 | 下游超时、触发限流、降级表现各一条 |

**话术**：先给结论与分数，再说阻断项，最后给能直接照做的补全动作。不要只说「覆盖不足」。

## 四、缺陷沉淀（没有脚本也能攒知识）

### 15 个高频缺陷模式

| 编号 | 模式 | 关键词 | 根因线索 | 修复方向 |
| :--- | :--- | :--- | :--- | :--- |
| DP-01 | 空值未防护 | 空、null、未传 | 校验缺失或只在前端 | 服务端补必填与类型校验 |
| DP-02 | 边界未覆盖 | 超长、越界、上限 | 只测等于没测略大略小 | 三位置各补一条 |
| DP-03 | 幂等缺失 | 重复提交、两次 | 无幂等键或唯一约束 | 幂等键 + 唯一索引 |
| DP-04 | 并发竞态 | 并发、超卖、锁 | 先查后改没加锁 | 行锁/版本号/串行化 |
| DP-05 | 状态机越迁 | 状态、取消、已支付 | 缺前置状态校验 | 统一状态机拒绝非法流转 |
| DP-06 | 超时重试放大 | 超时、重试、雪崩 | 无上限与退避 | 超时+退避+熔断降级 |
| DP-07 | MCP 连接失败 | 握手、端口、环境变量 | 命令/变量/网络问题 | 绝对路径、注入变量、端口检查 |
| DP-08 | 工具参数契约不符 | 参数、schema、必填 | 描述含糊、无校验 | 补描述与结构化错误 |
| DP-09 | 缓存不一致 | 缓存、脏读、过期 | 写路径未失效缓存 | 写后失效 + 合理 TTL |
| DP-10 | 资源泄漏 | 内存、句柄、连接池 | 异常分支未释放 | try-finally + 上限监控 |
| DP-11 | 权限越权 | 越权、403、鉴权 | 只认证不鉴权 | 资源级授权，默认拒绝 |
| DP-12 | 模型输出不稳定 | 幻觉、编造、不一致 | 无输出约束与基线 | 结构校验 + 固定评测集 |
| DP-13 | 提示注入 | 注入、忽略指令、泄露 | 数据与指令未隔离 | 隔离 + 工具白名单 |
| DP-14 | 时区与编码 | 时区、乱码、UTC | 未统一存储与编码 | UTC 存储 + 显式 UTF-8 |
| DP-15 | Agent 死循环 | 循环、重复调用、步数 | 无终止条件与步数上限 | 终止规则 + 三层限制 |

### 沉淀规则

- 一条只记一个缺陷；不可重现也要记，注明频率。
- 实际结果只写真实跑出来的，不推测。
- 每次记完，用标题和实际结果里的关键词回查历史记录，能对上就把编号写进「历史相似」。
- 同一模式出现 3 次以上，就在团队周会上提一次系统性修复，而不是逐个修。

## 五、运行时排障（基础设施层）

> 只做 Agent 与 Skill 本身的问题；应用崩溃、内存泄漏、渲染卡顿不在范围内。

### 1. Skill 行为漂移

- 同一输入在新版本输出是否变短、变空、结构变了？
- 对比两版系统提示、工具描述、模型参数，一次只改一项做二分。
- 判定：意思明显变了或关键字段丢失即算漂移；只是措辞不同不算。
- 回归：恢复基线配置重跑同一批输入，连续 3 次稳定再发布。

### 2. 跨引擎不一致

- 同一用例在两个引擎：判定是否一致？输出是否一致？工具选择是否一致？
- 同输出不同判定 → 判定脚本或阈值不一致，不是模型问题。
- 输出差异大 → 采样参数、上下文窗口、工具描述不同。
- 回归：两引擎重跑同一批用例，差异为 0 或已登记为允许差异。

### 3. MCP 调用失败

- 启动命令存在吗？换绝对路径或 `npx -y` 能起来吗？
- 配置里的 `${VAR}` 在客户端进程里能看到吗？改完重启客户端了吗？
- 远程地址端口通吗？鉴权头对吗？
- 工具列表为空：Server 没启动、握手失败、工具重名被过滤。
- 安全：配置里不要出现明文密钥；出现了就换掉并轮换。

### 4. Agent 死循环

- 数一数：同工具同参数调用了几次？总步数多少？
- 看轨迹：是否 A→B→A→B 往复？是否每轮输出都一样？
- 补三层限制：提示层终止规则 + 运行时最大步数 + 预算与超时。
- 改工具返回：让「无结果」也带原因，模型才有新信息可判断。
- 回归：同一轨迹重跑，同工具同参数 ≤2 次且正常终止。

### 排障报告模板

```
问题分类：行为漂移 / 跨引擎不一致 / MCP 调用失败 / Agent 死循环
证据：步骤号 / 相似度 / 端口 / 变量名 / 重复次数
根因定位：按可能性排序，每条都要能对上证据
修复建议：先改哪个、怎么改、改完看什么
回归验证：用什么输入重跑、通过标准是什么
```

## 六、使用原则

3. 用户答不出时不给安慰分，直接记错并给出下一步动作。
