# 用例质量门禁判定口径

与 `scripts/case-gate.js` 的 `CHECKS` 一一对应，供评审核对与二次开发。SKILL.md 只给结论，口径在这里。

## 1. 输入与输出

- 输入：`schema/testcase.schema.json` 的数组，或 `{ "cases": [...] }`。
- 输出：`schema/review-report.schema.json`，含 `verdict / score / risk / coverage / checks / gaps / stats / fieldIssues`。
- 通过条件：`score >= --min`（默认 70）**且** 四项关键检查全部命中；否则退出码 1。

## 2. 评分公式

- 检查共 23 项，权重合计 24。
- `score = 命中权重和 / 24 × 100`，四舍五入取整。
- 维度得分同理，按该维度权重归一。
- 风险分级：`score < 50`、负例边界不足、或关键项未过 ≥2 项 → 高；`score < 75` 或关键项未过 1 项 → 中；否则低。

## 3. 逐项口径

### 功能覆盖（权重 5.5）

| ID | 权重 | 判定口径 | 常见反例 |
| :--- | ---: | :--- | :--- |
| F1 | 1 | 至少一条非负例、P0/P1 的用例 | 全是 P2/P3，或全是异常场景 |
| F2 | 1.5（关键） | 负例或 `method=边界值` 的占比 ≥40% | 8 条用例只有 1 条异常 |
| F3 | 1 | 文本命中权限/角色/越权/未登录/鉴权 | 完全没有未登录场景 |
| F4 | 1 | 命中状态/连续/重复/中断/恢复/回滚/重试/并发 | 只有单次操作，没有状态变化 |
| F5 | 1 | 模块数 ≥2 | 只测一个模块却没声明范围 |

### 数据设计（权重 5.5）

| ID | 权重 | 判定口径 | 常见反例 |
| :--- | ---: | :--- | :--- |
| D1 | 1.5（关键） | 存在 `method=边界值` 且文本含等于/略大/略小/上下限 | 写了边界值，数据只给「超长」 |
| D2 | 1 | 命中空值/为空/不填/null/空字符串 | 只有「输入正确手机号」 |
| D3 | 1 | 命中超长/特殊字符/emoji/中文/空格/XSS/SQL/注入 | 只测正常文本 |
| D4 | 1 | 命中非法/格式/类型/非数字/负数/小数/超范围 | 金额只测 100 元 |
| D5 | 1 | ≥80% 用例的 `data` 是具体值 | 大量写「任意」「随便」 |

### 可执行性（权重 5）

| ID | 权重 | 判定口径 | 常见反例 |
| :--- | ---: | :--- | :--- |
| E1 | 1 | ≥80% 用例有前置条件 | 前置条件全空 |
| E2 | 1.5（关键） | 含「并且/然后/同时/接着」的步骤 ≤10% 且步骤非空 | 一步写「输入账号密码并点击登录」 |
| E3 | 1.5（关键） | ≥80% 预期可判定（≥6 字且非「正常/正确/成功/符合预期」） | 预期写「显示正常」 |
| E4 | 0.5 | 无「见用例/依赖上一条/承接」 | 用例 B 依赖用例 A 的数据 |
| E5 | 0.5 | 编号与标题均唯一 | 复制用例忘了改编号 |

### 集成与契约（权重 4）

| ID | 权重 | 判定口径 |
| :--- | ---: | :--- |
| I1 | 1 | 命中错误码/状态码/error/message/4xx/5xx |
| I2 | 1 | 命中幂等/重试/重复提交/重复请求 |
| I3 | 1 | 命中超时/限流/熔断/降级/并发 |
| I4 | 1 | 命中联动/前台/下游/上游/同步/回调/通知 |

### 非功能（权重 4）

| ID | 权重 | 判定口径 |
| :--- | ---: | :--- |
| N1 | 1 | 命中性能/并发/压测/响应时间/QPS/TPS |
| N2 | 1 | 命中安全/越权/注入/XSS/SQL/鉴权/脱敏/敏感 |
| N3 | 1 | 命中兼容/浏览器/分辨率/机型/版本/iOS/Android |
| N4 | 1 | 命中日志/埋点/监控/告警/trace/链路 |

## 4. 判定边界与豁免

- **关键项是硬门槛**：即使总分 90，只要负例边界不足、边界未落三位置、存在多动作步骤、或预期不可判定，仍判不通过。
- **纯文档/配置变更**可下调 `--min`（如 55），但四项关键项不放宽；同时应在报告里声明本期范围。
- **不判「用例写得对不对业务」**：门禁只看可执行性与覆盖结构，业务正确性需人工评审。模型在解释时必须说明这一点，避免把评分当业务结论。
- **关键词判定有局限**：文本里出现「安全」但实际没测安全，也会命中。门禁给的是线索，评审结论要模型复核并在报告中注明命中依据。

## 5. 与旧版校验的关系

旧脚本只查三个硬指标（负例+边界 40%、边界三位置、一步一操作）。现在这三项保留为 F2、D1、E2 三个关键项，并新增预期可判定（E3）作为第四个关键项；同时把「生成时自我约束」改成「评审时判定依据」，其余 19 项用于给出覆盖率与补全建议。

## 6. CI 用法

```bash
node scripts/case-gate.js --file cases.json --min 80 --json > gate.json || exit 1
```

`verdict=fail` 时退出码为 1；`gaps` 可直接作为评论回写到 PR，`missingScenarios` 适合贴进需求单。
