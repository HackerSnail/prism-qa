# 五层能力模型说明

面向评审与二次开发：解释模型从哪来、怎么判、怎么更新。SKILL.md 只放路由，细节在这里。

## 1. 为什么是这五层

依据是 2026 年测试岗位的结构性变化，而不是把热门词堆在一起：

- 手工测试需求同比下降 47%，AI 测试岗位需求同比增长 455%——存量人群在被动流入新岗位。
- 大厂 JD 出现硬性要求：「熟悉 MCP 协议优先」「有 Skill 封装和工程化落地能力」。
- 测试人的技能树被描述为「AI 驯化」：写得出可复现的 Prompt、看得懂 Agent 轨迹、封得出可分发 Skill、接得通 MCP、测得了非确定性输出。

五层正好覆盖从「会写 Prompt」到「能交付 Agent 质量方案」的跃迁路径，且每层都有可观察的产出，能落到评分上。

## 2. 五层定义

| 层 | key | 权重 | 定义 | 可观察行为 |
| :--- | :--- | ---: | :--- | :--- |
| Prompt 工程 | prompt | 20% | 把测试意图写成可复现指令 | 同一 Prompt 多次运行结构一致、结果可判定 |
| Agent 理解 | agent | 20% | 理解规划—行动—观察循环与工具调用 | 能画出轨迹并解释每步为什么这么走 |
| Skill 封装 | skill | 25% | 把能力封装成可分发单元 | 别人装了不看解释也能触发并跑对 |
| MCP 协议 | mcp | 15% | 理解原语、能配置与排查 Server | 能定位失败发生在连接、握手还是执行层 |
| AI 测试专项 | specialty | 20% | 非确定性系统的测试设计 | 能写出可判定预期与回归基线 |

Skill 封装权重最高，因为它是这次转型里最稀缺、也最难被工具替代的一层。

## 3. 题库结构

`data/questions.json` 的 `banks`：

| bank | 题量 | 是否进雷达 | 说明 |
| :--- | ---: | :--- | :--- |
| prompt / agent / skill / mcp / specialty | 各 10 | 是 | 每层含场景、代码、Prompt 调试三类题 |
| infra | 72 | 否 | 原 Linux 题，作为前置检查（`--with-infra`） |
| basics | 125 | 否 | 原测试基本功题，保留为 `--basics` 面试回练 |

题目字段：

```json
{
  "id": "P03",
  "type": "prompt",          // scenario | code | prompt
  "q": "问题",
  "ans": "参考答案",
  "must": ["只输出"],         // 全部命中才算对，用于代码/调试题
  "accept": ["围栏", "示例"], // 任一命中即可，用于场景题
  "blind": "apply",          // command | concept | process | apply
  "level": 3                 // 1 基础 / 2 进阶 / 3 难点
}
```

判分规则：`must` 全中且 `accept` 任一命中 → 正确；只有 `must` 时全中即可；只有 `accept` 时任一即可。关键词判分对同义表述有容错，但可能把「答到点但用词不同」判错——这是快照式诊断的已知局限，模型在解释时可按实际语义补充说明，但不得改动分数。

## 4. 评分与等级

- 单层得分 = 该层答对数 / 该层抽题数 × 100。
- 总分 = Σ(层得分 × 权重)，权重和为 1。
- 等级：L4 可交付 ≥85｜L3 实战期 70–84｜L2 上手机 40–69｜L1 起步期 <40。
- 基础设施层单独给分，正确率 ≥60% 视为达标；不达标时报告顶部提示先补日志/进程/端口/资源基本功。
- 抽题默认每层 6 题（共 30 题），可用 `--n` 调整，最少建议 3 题，否则单层分数粒度太粗。

## 5. 归因与复练

错题按四类归因，用于决定下一步是「补概念」还是「练动手」：

| blind | 展示名 | 含义 | 对应动作 |
| :--- | :--- | :--- | :--- |
| command | 记不牢 | 命令/参数记不住 | 做命令卡，每天 5 条 |
| concept | 概念不清 | 概念混淆或缺失 | 读定义 + 用自己的话复述 |
| process | 流程说不清 | 知道元素但串不起来 | 画流程图，按步骤复述 |
| apply | 会说不做 | 说得出但落不了地 | 立刻做一个小练习并留产物 |

`data/progress.json` 保存历史与最近错题，下一轮抽题优先命中错题；连续两次答对后自然被新题稀释，不需要手动清理。

## 6. 学习路径选择

- 取分数最低的 1–2 层（<70 分）生成路径；全部 ≥70 时取最低层的 `high` 档，给巩固任务。
- band：`low` <40、`mid` 40–69、`high` ≥70。
- 路径必须来自 `data/learning-paths.json`，模型不得自造课程与链接；需要更细的计划时，只能把 `actions` 拆成周计划。

## 7. 月度更新 SOP

1. 每月收集一轮大厂 AI 测试 JD 与社区高频面试题，标记新增要求。
2. 每层新增 2–3 题，优先补「现有题没覆盖的可观察行为」；同步更新 `meta.updated`。
3. 旧题只修订不删除，保证历史成绩可比；确需下线时在 `meta` 记录原因。
4. 新增题必须给 `must` 或 `accept`，并自测一次判分是否符合预期。
5. 更新后跑 `examples/answers-demo.json`，确认雷达与路径输出没有异常。
